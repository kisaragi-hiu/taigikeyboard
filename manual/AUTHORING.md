# Authoring the desktop user manual

`README.md` is the manual: Markdown and pictures for first-time desktop users (macOS, Windows, Linux), readable on GitHub as it is. A cheatsheet picture and the blog post that announces them sit beside it. Sources live here, like `launch-film/`; the website repository (`taigikeyboard/taigikeyboard.github.io`) receives copies.

| Path | What it is |
|---|---|
| `README.md` | The manual. Markdown only — no HTML page, no stylesheet, no script. |
| `keyboards/` | Keyboard pictures: which keys do what, one per topic and platform. Generated by `keyboards.py` — never edit by hand. |
| `shots/` | Screenshots of the real candidate window, panels and settings window. Generated — never edit by hand. |
| `cheatsheet.html` | Source of the cheatsheet picture, not a page to publish; `?os=pc` switches it to Windows / Linux key names. |
| `cheatsheet/` | The rendered cheatsheets (3200 × 2000). |
| `blog/` | Posts written for the website's future blog, with Jekyll front matter. |
| `render.sh` | Renders `keyboards.py` and `cheatsheet.html` to PNG with headless Chrome. |

## Regenerating the pictures

```sh
manual/render.sh        # keyboards/*.png and cheatsheet/*.png
```

The keyboard pictures are drawn by `keyboards.py` from tables in that file: the two layouts (MacBook, Windows with a navigation block), the keys each picture marks, and the full-width punctuation map. Change a default key in `desktop/crates/taigi-desktop-core/src/keys/` or a row of `policies/full_width.rs` and the matching table there changes with it.

The screenshots come from `macos/Tests/TaigiInputMethodCoreTests/ManualScreenshotTests.swift`, which types into the real controller and engine, lets the real windows come up, and captures the screen. Run it after a UI change, on a Mac whose terminal has Screen Recording permission (a Retina display gives 2x pictures):

```sh
make build                                   # only if engine/ or desktop/ changed
TAIGI_MANUAL_SHOTS="$PWD/manual/shots" swift test --package-path macos --filter ManualScreenshotTests
manual/render.sh                             # the cheatsheet embeds three of the screenshots
```

Windows flash on screen for about half a minute while it runs. A new picture is a new `Scene` in that file plus an image line in `README.md`.

## Publishing to the website

Jekyll renders `README.md` as the index of its directory, so the manual is served at `https://taigikeyboard.tw/manual/` by copying the page and its pictures into the website repository's `manual/`:

```sh
SITE=../taigikeyboard.github.io
mkdir -p "$SITE/manual"
cp -R manual/README.md manual/keyboards manual/shots manual/cheatsheet "$SITE/manual/"
```

Then link the page from the website's `_includes/navbar.html`.

The website has no blog yet. When it gets one, the files in `blog/` go into its `_posts/` unchanged; they link to `/manual/` and to pictures under `/manual/shots/`.

## Writing rules

- Text is Taigi in Hanji, matching the website. UI labels are quoted from the `hanji` values in `i18n/*.json` — copy them, do not reword.
- State what a key does and stop. No slogans, no reader personas, no promises about how fast it is to learn.
- Every key is written for both platform families — a `macOS` column and a `Windows、Linux` column — and every topic whose keys differ gets one keyboard picture per family. A behaviour only one desktop has (the Shift tap for English on Windows) is said in words next to the picture.
- The "平台的差別" table at the top lists every difference; a new platform difference goes there first.
- Defaults come from `desktop/crates/taigi-desktop-core/src/keys/` (`action.rs`, `shortcut_actions.rs`, `shortcut_labels.rs`, `intent.rs`).
