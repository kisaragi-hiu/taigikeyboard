# Maintainability audit — all scopes (engine, mobile, desktop, tests, naming, docs)

Status: **audit only, nothing decided, no round open.** USER 2026-09-30 asked for five things: (1) platform code duplicated across shells that could move into the engine, (2) engine crates with high cohesion and low coupling, (3) cross-platform consistency so AI-driven drift stops accumulating, (4) a test review that removes redundant tests and lets a change run only the tests it touches, (5) folder / file / symbol naming that is consistent, simple and matches what the thing does. No release scope is implied; open USER decisions are listed at the end.

Sources: six read-only passes on `30a79c16` (dead surface, platform twins, redundant fallbacks + layering, docs drift, tests, naming). Rows marked **verified** were re-checked by hand in the main session; every other row carries the pass's `file:line` and must be re-grepped before a round quotes it. Counts marked `~` exclude generated code (`*.pb.swift`, Android `engine/proto/*.java`, `Strings/Generated/`, `i18n/generated/`).

Companions: `2026-09-24-mobile-smart-suggestions-brainstorm.md` §3 (engine + mobile audit; R1–R5 there are done except the items re-listed below) and `2026-09-24-open-source-readiness-and-layout.md` §3–4 (repo layout; rounds 0–5 done, 6–10 open). This report does not repeat their rows.

Axis tags used in §2: **E** = move into the engine (ask 1) · **C** = engine cohesion / coupling (ask 2) · **P** = cross-platform parity (ask 3) · **T** = tests (ask 4) · **N** = naming (ask 5) · **D** = dead surface · **X** = docs drift.

---

## 1. Summary

The tree's biggest maintenance cost is **the same behaviour written four or five times on the platform side**: candidate commit resolution (candidate → document text, auto-space, usage record) exists in Swift ×2, Kotlin and Rust; Windows and Linux carry a byte-identical settings search file, a near-identical key-intent executor and a near-identical settings-page model outside `desktop/`; macOS re-implements ~4,000 lines that `desktop/crates` already provides. Drift has already landed in three user-visible places (Android's Dictionary tab ignores the custom-dictionary toggle; Android drops a next-word pair when a candidate ends in sentence punctuation; the English placeholders for the custom-entry dialog are swapped) and one bug candidate (iOS renders hanji-less candidates on the TPS layout through the numeric converter).

Inside the engine the crates are acyclic and mostly cohesive, but `dispatch` is too thick (1,293 lines of user-data page logic that belongs in `userdata`), `lexicon` exports ~20 symbols that only `composing` uses, and the "temporary until P5" seams (store traits, `desktop-core → userdata`, the `desktop-storage` re-export shim) outlived P5.

The test suite is large (≈3,900 tests, ≈57 k lines) and slow by construction: 68 integration binaries each link the whole crate graph, the 37 MB `dictionary.csv` is re-read ~13 times per run, and about 60 tests restate engine behaviour through a platform bridge or a second engine entry point. Swift tests (iOS 357, macOS 857) have no CI at all, so "run only what changed" can only save time where CI already runs.

Naming carries retired-feature vocabulary (`isTranslateSwapped`, `LexiconService`, `legacyAppearance`, `smartbar/`, `Composition/`), two spellings of the same concept on either side of every boundary (`hanji`/`hanzi`, `toneless`/`notone`, `assoc`/`association`, `subcoll`/`subcollections`) and wrappers that invert the proto method name (`customDictionaryList` for `list_custom_entries`).

**Recommended first round:** R1 dead-surface deletion (delete-only, ~500 LOC, no design decisions) followed immediately by the three verified parity bugfixes in R2. Both unblock nothing and remove noise before the structural rounds R3–R6 change the engine surface.

## 3. Justified-looking layers (do not re-flag)

- **Crate graph is acyclic and the leaf crates are cohesive**: `phonetics`, `nextword`, `mmap-host`, `protos`, `swift-ffi` (190 lines), `android-jni` (285 lines). The per-crate `dispatch.rs` + `handle.rs` pair is the Path G proto boundary (`rust-best-practices.md` §8), not duplication.

- **Candidate layout and theme colour maths stay platform-side** (`cross-platform-alignment.md` §4.1); the split-cell builders and `KeyboardColorSettings` twins match byte-for-byte and are excluded.
- **Deliberate test seams**: `sendRawBytes`, `panicForTestRaw`, `resetDiagnosticsForTesting`, `Phase::composing_display` (§10.2 oracle), `FilterPredictions` (internal rewrite target of `PredictNext`), `AssocLookupRequest` / `LexiconAssocEntry` (internal DTOs), `DeriveCustomQueryKey` (Windows + Linux settings search), `formatTemplate` / `format_template` (i18n generator contract), `AppConfig.platform_id` (nextword rejects UNSPECIFIED), `UserDataResponse.usage_recorded` (fire-and-forget ack).

- **`INVARIANT_*`-labelled tests** are protected by `tools/invariant_labels.py`; any test deletion must keep every documented label named in some test file.
- **iOS / Android theme + settings twin tests** test each platform's own code — not redundant.
- **TPS being mobile-only**, forced `oo` / `nn` double-tap folds on desktop, Win/Linux reading the custom-dictionary store directly for settings search (`behavioral-invariants.md` ~§650), Android's fetch threading (`ComposingManager.kt:412-419`) — all recorded.
